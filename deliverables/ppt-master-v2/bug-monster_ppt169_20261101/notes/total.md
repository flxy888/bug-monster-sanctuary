# 01_把Bug变成怪兽

大家好，这次展示的项目叫 Bug 怪兽收容所，是一个基于 Java 静态解析的代码质量练习系统。它把常见代码问题映射成怪兽，让用户通过发现问题、修复代码和重新扫描，完成一次有反馈的收容。当前交付面向本机单用户课程演示，下面先从一个具体疏漏说明它要解决什么问题。

---

# 02_一个分号的问题

这段代码来自项目的 VIP 优惠案例。if 条件后多了一个分号，于是 then 分支已经结束，后面的折扣代码块独立执行，普通订单也会得到折扣。系统会把空 then 分支标记成空壳潜伏者，并提供位置和建议。项目希望让发现、理解和修复连成一次练习；页面里的省略号只用于展示节选，完整业务类保存在样例目录。

---

# 03_收容闭环

用户首先提交完整 Java 源码，扫描后查看问题的行号、建议和怪兽，再在草稿里修改，最后通过再次扫描验证收容。修改草稿本身不会自动获得奖励，判定仍由后端完成。这里需要区分两个反馈：质量分对应本次代码存在的问题，经验值对应首次有效修复带来的成长，两者不能混在一起。

---

# 04_五类代码怪兽

系统目前有五项规则。空 catch 没有实际处理时对应吞异常兽，每个问题扣十五分；方法体超过三十源行对应长舌章鱼，扣十分，其中空行和注释也计入源行。控制结构达到四层对应套娃怪，扣十分；普通方法超过五个参数对应多手触手怪，扣八分；空 then 分支或多余分号对应空壳潜伏者，扣八分。质量分从一百分扣起，最低为零。这些阈值是项目定义的启发式规则，用来帮助练习，并不是对代码正确性的完整证明。怪兽素材是本项目自绘的像素 SVG。

---

# 05_AST静态解析

扫描时，后端按 Java 二十一的语法配置，使用 JavaParser 把源码解析成抽象语法树，根节点是 CompilationUnit。五项规则遍历各自关心的节点，汇总问题、行号、建议和扣分，形成扫描结果。这个过程只解析，不编译或执行用户提交的代码。语法失败会返回结构化错误，也不能直接发修复奖励；解析成功同样不能保证业务逻辑正确。

---

# 06_接口与多态

这一页展示实际的 AnalysisRule 接口，每个规则都需要返回自己的规则编号，并实现检查方法。空 catch、长方法等五个规则分别实现这个接口，处理各自的问题。CodeAnalyzer 接收规则集合，筛选启用项并统一汇总结果。这样，接口和多态负责组织规则，集合和 Stream 负责统一处理，课程知识就落实到了具体代码结构里。

---

# 07_系统结构

系统采用前后端分离。Vue 三和 Monaco 负责代码编辑、问题定位，以及图鉴、成长、历史和 AST 的展示，通过 REST 请求 Spring Boot 单体后端。后端由 Controller 接收请求，Service 协调扫描和结算，规则实现执行静态检查，再由 MyBatis 访问 MySQL。数据库保存项目和源码快照、问题身份与谱系，以及奖励和成长记录。经验值只由后端结算，前端展示真实返回结果。

---

# 08_空catch修复

订单 CSV 导入时，金额解析可能抛出 NumberFormatException。原来的 catch 没有处理语句，异常会被忽略，页面中的空处理注释只是演示标记。修复时在 catch 中补充 ImportFailure，记录失败条目的行号和金额错误原因，再把它加入失败列表。完整样例的质量分会从八十五分提高到一百分，消除一个空 catch 问题。这里是既有样例的分数说明，现场结果以实际页面为准。

---

# 09_空if修复

再回到开头的 VIP 案例。修复动作只需要删除条件后的多余分号，保留后面的花括号和折扣逻辑，让折扣代码重新受 VIP 条件控制。再次扫描后，样例消除一个空 if 问题，质量分从九十二分提高到一百分。不过，规则不再命中只能说明这项静态检查通过，不能据此声称整个业务已经完全正确。

---

# 10_奖励与防重

首次有效收容获得二十点经验值。系统在成功扫描之间比较问题的稳定身份和谱系，而不是仅凭行号或问题消失就发奖。重复扫描没有新的有效收容，语法失败无法确认修复，删除方法不能作为正常修复，身份匹配存在歧义时则保守冻结。已经领奖的问题复发后再次修复，也不会再次新增奖励。项目行锁、唯一奖励记录和事务共同维持结算幂等性。

---

# 11_持久化与历史

系统共有九张表，这里按照用途做了展示性整理。基础对象包括用户、项目和怪兽定义；扫描证据包括扫描运行、问题明细和问题谱系；成长与结算包括用户怪兽、奖励日志和项目身份状态。源码快照保留历史上下文，当前草稿和累计成长另外维护，因此查看历史并不等于回退当前成长记录。这些表及增量变化都能在 database 目录追溯。

---

# 12_AI修复预览

在狼尊主题下，用户可以主动点击 AI 修复。当前源码会发送给 DeepSeek，返回原代码、新代码预览和摘要，用户确认后只应用到草稿。AI 本身不会新增扫描，也不会发经验值；仍然需要重新提交扫描，由原有后端规则独立判定问题、收容和奖励。发生错误、取消或上下文变化时会保留原稿，生成建议也需要人工检查。现场展示不预设固定响应时间。

---

# 13_现场演示

现场可以双击根目录的启动演示命令，等待就绪后打开本机页面。先扫描订单导入或 VIP 优惠案例并定位问题，再修改草稿、重新扫描，观察质量分、收容结果和新增经验值。接着打开图鉴、成长、历史和 AST，重复扫描确认同一个奖励不会重复发放。如需展示首次奖励，可以使用新建项目，保留原审计记录。时间允许时保存昵称狼尊九九九，展示紫色主题与角色过场，再主动生成 AI 预览；所有数值以实际页面为准。
